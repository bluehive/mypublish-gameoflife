##### 【三角ロジック】

| 要素 | 内容 |
|------|------|
| **データ** | 遠くから「絵を描け」と伝えたいとき、文字列をそのまま実行すると危険である。許可した命令だけを、入れ子のリストで表す方法がある。 |
| **ワラント** | プログラムをデータと同じ形で扱いたいなら、この思考実験の範囲では、単純な入れ子の代表格はリストである。 |
| **主張** | 丸括弧の連なりは気まぐれな発明というより、その条件を削ぎ落とした先に現れやすい形——発見——に見える（原記事の見方）。 |

#### J.1 思考実験：命令を「安全なデータ」にする

画面に線を引くプログラムがある、とします。手元なら `draw-line` を呼べばよい。困りごとを一つ足します。**遠くから送られてきた描画の指示を、こちらで実行したい。**

最初の思いつきは、「相手が送った文章を、そのままプログラムとして走らせる」ことです。これは強すぎます。描画以外のことまでできてしまう。だから **こちらが許可した指示だけ** を、データの形で受け取ります。

この付録でいう **命令** は、次のカード1枚のことです。「青い線を、点Aから点Bへ引け」。

```text
名前: draw-line
材料: 点A, 点B, "blue"
```

「名前」「材料」という欄名は毎回同じなので、省けます。残す規則は一つです。**いちばん左がすること、右が材料。**

```text
["draw-line", 点A, 点B, "blue"]
```

これも同じ命令です。意味は「点Aと点Bを `"blue"` で結べ」。思考実験では、カードを見やすくするために角括弧を使います。本編の `cond` の枝や、値としての `(list …)` とは別の書き方です。

材料の中に、別の命令を入れたくなることがあります。

```text
["rotate", ["draw-line", 点A, 点B, "blue"], 90]
```

これは2枚のカードです。

- 内側: `["draw-line", 点A, 点B, "blue"]` … 青い線を1本引く  
- 外側: `["rotate", （いま引いた線）, 90]` … その線を 90 度回す  

読み方は、次の2段です。上の `rotate` の例で追います。

1. **角括弧で始まらないもの**は、すでに材料そのものです。点A、点B、`"blue"`、数の 90 がこれです。  
2. **角括弧で始まるもの**は命令です。いちばん左（`draw-line` や `rotate`）は「どの作業か」の名前です。右にある材料を先にそろえてから、その作業をします。

いちばん左は、材料ではありません。あらかじめ用意した作業の一覧から、同じ名前の作業を取り出します。`draw-line` と書いてあれば「線を引く作業」を取り出す、ということです。

順番は **内側から** です。先に内側の `draw-line` で線を作り、その線と 90 を材料にして `rotate` します。序章 0.4 の「内側から外側へ計算する」と同じ向きです。

ここまでは「線を引け」「回せ」だけです。次の三つを足すと、**自分で新しい作業を定義して呼び出せる**ようになります。プログラム言語がしている仕事の一部と同じです。

- `do` … カードを上から順に実行する  
- `def` … 結果や作業に名前を付ける  
- `fn` … 「今は動かさず、あとで使う作業」を作る  

本編の `define` は、`def` と `fn` を一つの語で引き受けます（第1章 1.3）。`do` は本線 BSL には出てきません。ここでは「まとめ役」だとだけ覚えてください。

安全な命令カードを作ろうとしただけなのに、気づけば小さなプログラミング言語を書いています。

#### J.2 コードがデータであること

ここまで作った「角括弧の命令」には、JavaScript や Python のような **キーワードが先に決まっている言語** にはない手触りがあります。

たとえば JavaScript の `const` は、言語が決めた書き方です。利用者が `c` に改名することはできません。作者の作法に従う **ゲスト** です。角括弧の命令では、`def` も `draw-line` も同じ形のリストです。最初から付いていた作業と、自分で足した作業の差が、書き方の壁としては薄い。原記事はこれを **共同経営者** に近い、と書いています。

命令がリストなら、命令を書き換えることも、リストの組み替えです。

```text
["unless", 条件, 本体]
    ↓ 先頭を if に替え、条件の前に not を置く
["if", ["not", 条件], 本体]
```

JavaScript や Python では、まず文を木に分解する道具（パーサ）が要ります。こちらでは、左端と中身を組み替えるだけで済みます。いわゆるマクロです。本編では扱いません。

編集も、文字ではなく枝単位にできます（Paredit など。発展）。具体例です。

```text
いま:   ["if", 条件, 本体]
操作:   「条件」の外側に not の箱を被せる
あと:   ["if", ["not", 条件], 本体]
逆操作: 箱を剥がすと、元の ["if", 条件, 本体] に戻る
```

要するに、**プログラムそのものが、いつものデータ操作の対象**になります。

#### J.3 種明かし：それは Lisp の見た目である

見た目を3つだけ変えます。角括弧を丸括弧にする。カンマを消す。名前を、引用符のない語（記号）にする。すると、本書の式と同じ家族に見えます。

次の例では、役割を色で分けません。引用符の有無で分けます。

- `"blue"` … 色の文字列。**値そのもの**なので、引用符を残す。  
- `"left"` / `left` … 名前。表を引いて中身（点など）に替える。  
- `点L` … すでに点なので、そのまま材料。

```text
["do",
  ["def", "draw-triangle",
    ["fn", ["left", "top", "right", "color"],
      ["do",
        ["draw-line", "left", "top", "color"],
        ["draw-line", "top", "right", "color"],
        ["draw-line", "left", "right", "color"]]]],
  ["draw-triangle", 点L, 点T, 点R, "blue"]]
```

いちばん下の行に `"blue"` があります。三角形を青で描け、という材料です。

```racket
; 見た目を整えたもの（イメージ。本編 BSL の練習問題ではない）
(define (draw-triangle left top right color)
  (draw-line left top color)
  (draw-line top right color)
  (draw-line left right color))

(draw-triangle 点L 点T 点R "blue")
```

関数の本体では、並べた式を上から順に走らせるので、思考実験の `do` を書かなくてよい、という対応です。`define` が `def` と `fn` をまとめて引き受けます。最後の1行で、色の `"blue"` を渡しています。

原記事は Clojure で同じ対応を示しています。規則は共通です。`(draw-line left top color)` は、「`left` `top` `color` の中身をそろえてから、線を引く作業を走らせる」という意味です。

#### J.4 結論：削ぎ落とすとリストに着く

やりたかったことは一つです。**プログラムを、いつものデータと同じ形で書きたい。**

書き方の候補はいくつもあります。XML でも JSON でも書けます。飾りを外していくと、残るのは入れ子のリストです。Lisp の丸括弧は、そのリストの見た目です。

原記事は、これを気まぐれな発明というより、条件を詰めた先に現れやすい形——**発見**——だ、と述べます。もっと読みやすい表面があるかもしれない、とも残しています。本書の `(+ 1 2)` も、同じ家族の書き方です。
