---
title: "付録I　BSL の意味論メモ（define の裏側）"
---

> **この付録のゴール**  
> BSL の `(define (fun-pic f) …)` と `(define width 4)` が「裏側で何をやっているか」を、名前と値の結びつき（環境・置換モデル）の視点から理解する。  
> **対象**: 第1章 1.3「定数 `define`」を読んだあと、もう一段深く知りたい人向け（本編を読み進めるのに必須ではない）。  
> **Issue**: [#20](https://github.com/bluehive/mypublish-gameoflife/issues/20)

#### I.1 共通してやっていること

`(define (fun-pic f) …)` も `(define width 4)` も、やっていることは同じです。

どちらも **「名前を、ある値に結びつける」**。

Racket 本体ではだいたい次の形に展開されます:

```racket
;; (define width 4) の裏側
(define-values (width) 4)

;; (define (fun-pic f) (* f 100)) の裏側
(define-values (fun-pic)
  (lambda (f) (* f 100)))
```

つまり差は:

| 表の書き方 | 束縛される「値」 |
|------------|------------------|
| `(define width 4)` | 数 `4` |
| `(define (fun-pic f) …)` | **手続き（関数オブジェクト）**＝「`f` をもらって本体を計算する機械」 |

**名前の登録の仕方は同じ**で、**登録する中身が「普通の値」か「関数」か**だけが違います。

#### I.2 `(define width 4)` のとき

イメージ:

```text
定義テーブル（環境）
┌─────────┬──────┐
│ 名前    │ 値   │
├─────────┼──────┤
│ width   │  4   │
└─────────┴──────┘
```

1. 右辺 `4` を評価 → 値 `4`
2. 名前 `width` にその値を登録
3. 以後プログラム中の `width` は、テーブルを見て `4` に置き換わる

**計算手順は保存しない。すでに出来上がった値だけ覚える。**

#### I.3 `(define (fun-pic f) …)` のとき

表では「関数定義専用の糖衣構文」です。裏側ではだいたい:

```racket
(define fun-pic
  (lambda (f) (* f 100)))
```

と同じです。

イメージ:

```text
定義テーブル
┌─────────┬────────────────────────────────┐
│ 名前    │ 値                             │
├─────────┼────────────────────────────────┤
│ fun-pic │ 〈手続き〉                      │
│         │   引数: f                      │
│         │   本体: (* f 100)              │
└─────────┴────────────────────────────────┘
```

1. `lambda` 相当の**手続きオブジェクト**を作る  
   （「今すぐ `(* f 100)` は計算しない。レシピだけ持つ」）
2. その手続きを名前 `fun-pic` に登録
3. 本体の計算は、**呼ばれたとき**に初めて走る

HtDP / BSL の授業ではこれを「関数定義を定義テーブルに入れる」と言い、Racket 実装では **クロージャ／手続き値** です。

#### I.4 `(fun-pic width)` を評価するとき（両方が組み合わさる）

```racket
(define width 4)
(define (fun-pic f) (* f 100))
(fun-pic width)
```

だいたい次の順です。

```text
1. (fun-pic width) を見る
2. fun-pic → テーブルから「手続き」を取る
3. width   → テーブルから 4 を取る
4. 手続きを「適用」する:
     仮引数 f に 4 を結びつける
     本体 (* f 100) を (* 4 100) にして評価
5. 結果 400
```

置換モデル（教科書風）だと:

```text
(fun-pic width)
→ (fun-pic 4)           ; width を展開
→ (* 4 100)             ; 本体の f を 4 に置換
→ 400
```

**定数**は「値を取り出すだけ」。  
**関数**は「値を渡して、覚えておいた本体を走らせる」。

#### I.5 図で対比

```text
(define width 4)
        │
        ▼
   箱 width に 4 を入れる
   ※ 中身は「数」


(define (fun-pic f) (* f 100))
        │
        ▼
   箱 fun-pic に「機械」を入れる
   ※ 中身は「f を受け取って (* f 100) する手順」


使うとき:
  width          → 箱を開けて 4
  (fun-pic …)    → 箱を開けて機械を取り出し、… を材料に動かす
```

カッコ `( … )` は「機械を動かす」合図で、**名前自体にカッコが付いているわけではない**。

#### I.6 なぜ BSL は `(define (width) 4)` を拒否するか（裏側の視点）

フル Racket なら技術的には:

```racket
(define width (lambda () 4))  ; 引数0の手続き
```

も可能です。BSL は**言語の表面**でこれを禁止しています。

| | 定数 `(define width 4)` | 0引数関数（BSL禁止） |
|--|------------------------|----------------------|
| テーブルに入るもの | 数 `4` | 手続き（呼ぶと 4） |
| 取り出し | `width` | `(width)` |
| 学生が混乱しやすい点 | — | 「値なのに毎回呼ぶ」 |

**実装ができないのではなく、教育用に「定数と関数をはっきり分ける」ために弾いている**、という理解が正確です。第1章 1.3 の「なぜ『引数ゼロの関数』ではなく定数か（BSL）」と合わせて読むと、表面（いつ・何回計算するか）と裏側（登録される値の種類）の両方が見えます。

#### I.7 一行まとめ

- `(define width 4)`  
  → 名前に **完成した値** を登録する  
- `(define (fun-pic f) …)`  
  → 実際は `(define fun-pic (lambda (f) …))` 相当で、名前に **後で動く手続き** を登録する  
- 呼び出し `(fun-pic width)`  
  → 手続きを取り出し、`width` の値を引数に渡して本体を評価する  

「`define` の仕事はいつも名前付け。関数形だけ中身が lambda（機械）になる」——これが BSL のバックエンドの実体です。
