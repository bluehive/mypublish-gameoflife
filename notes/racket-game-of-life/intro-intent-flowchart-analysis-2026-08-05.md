## 4. 解析目標 B — 新概念の説明の長さ

### 候補概念と「序章で要る長さ」

| 概念 | 本書での初出 | 序章で必要な説明 | 本丸の章 |
|------|--------------|------------------|----------|
| 例 / Data Examples | 0.6, ch02 | **必須・短文**（入力と期待結果） | ch02 |
| check-expect | 0.6, ch01.9 | **必須・短文**（例の実行形） | ch01–02 |
| テンプレート / `...` | 0.6, ch02.1 | **必須・短文**（データの形→骨） | ch02 |
| 署名・目的・stub | ch02 パートB | **図のノード名＋各1行**で可 | ch02 |
| 記述・解釈 | ch02 パートA | 図の「データ設計」列で十分。長文は不要 | ch02 |
| 自己参照データ | ch02 | 序章は触れる程度（「リストは残りも同型」） | ch02 |
| big-bang | ch05.6 | 序章の意図図には**載せない**（発展） | ch05 |
| BSL の define 裏側 | 付録 I | 序章に**入れない** | 付録 I |

### 結論 B

- v1 の「長文禁止・図のみ」は**強すぎた**。
- 序章では **用語ミニ定義を 4–8 行**まで許容する（章を食わない長さ）。
- 「新概念の教科書的長文」はなお ch02 以降。0.8 は **用語の錨 + ループ図 + 章対応**。

本文に足すミニ定義（採用案）:

1. **例** — 具体的な入力と、先に書いた答え  
2. **check-expect** — その例を Run で確かめる形  
3. **テンプレート** — データの場合分けに沿った空き付きの骨（`...`）  
4. **stub** — まだ正しい計算をしない仮の本体  
5. **署名 / 目的** — 型の約束と、日本語1文の役割
