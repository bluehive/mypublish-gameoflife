title: "第2章　規則から次の世代を作る"

この章の仕事は、盤面を受け取って新しい盤面を返す `next-generation` を作ることです。一度に全部を書かず、セルの判定・近傍の集計・候補の選別に分けます。[全コード](life-draft.rkt)で同じ名前の定義をたどってください。

## 作る関数のつながり

最終的な入力は現在の盤面、出力は次の盤面です。ただし、盤面全体を直接書き換えることから始めると、どの部分で間違えたか分かりにくくなります。そこで、まず一つのセルだけを見る関数を考えます。

一つのセルの次の状態を決めるには、「今生きているか」と「生きている近傍はいくつか」の二つが分かれば十分です。座標そのものや、近傍がどの方向にあるかは、この判定には使いません。必要な情報だけを受け取る小さな関数にしておくと、盤面を用意しなくても規則を試せます。

その次に、座標と盤面から近傍の数を求める関数を作ります。最後に、調べる座標を集め、一つずつ次の状態を判定します。この順番なら、最後の関数はすでに確かめた部品を組み合わせて書けます。

## 2.1 1セルの規則を試す

```racket
;; next-alive?: Boolean Number -> Boolean
;; n は0〜8の整数
(define (next-alive? alive-now? n)
  (cond
    [alive-now? (or (= n 2) (= n 3))]
    [else (= n 3)]))

(check-expect (next-alive? #true 2) #true)
(check-expect (next-alive? #false 2) #false)
(check-expect (next-alive? #false 3) #true)
(check-expect (next-alive? #true 4) #false)
```

同じ「近傍2」でも、現在の生死で結果が違います。入力を二つに分ける理由です。練習：近傍0、3、8の生セルの答えを予想し、テストを追加してください。

### 規則から式を読む

`alive-now?` は現在の生死を表す真偽値です。`cond` の最初の条件にそのまま置けるので、真なら生セルの枝へ進みます。その枝の `or` は、二つの条件のうち少なくとも一つが真なら真になります。「近傍が2、または3」という日本語を、この形で表しています。

現在が死なら最初の条件が偽なので、`else` の式を計算します。こちらは近傍が3かだけを調べます。戻り値も真偽値なので、後で「真なら次の盤面に入れる」という使い方ができます。この関数はリストを変更せず、次に生きるかどうかを答えるだけです。

近傍3のときは現在の生死にかかわらず真ですが、近傍2のときは答えが分かれます。こうした分かれ目をテストすると、条件の取り違えを見つけやすくなります。練習の近傍0、3、8の生セルの答えは、順に偽、真、偽です。周囲の数が増えれば常によいという規則ではないことも、数値の例で確認できます。

## 2.2 周囲だけを数える

`shift-cell` は座標をずらし、`cell-neighbors` は8方向の座標をリストにします。中央自身は含めません。

```text
(-1,-1) (0,-1) (1,-1)
(-1, 0)   中央   (1, 0)
(-1, 1) (0, 1) (1, 1)
```

### 座標をずらして近傍を作る

左上に移るならxとyをそれぞれ1減らし、右に移るならxに1を足してyをそのままにします。この「どれだけずらすか」を `dx` と `dy` という二つの引数で表します。

```racket
(define (shift-cell cell dx dy)
  (make-posn (+ (posn-x cell) dx)
             (+ (posn-y cell) dy)))

(check-expect (shift-cell (make-posn 2 2) -1 0) (make-posn 1 2))
(check-expect (shift-cell (make-posn 0 0) -1 -1) (make-posn -1 -1))
```

元の `cell` のxとyを読み取り、ずらした数で新しい座標を作っています。元の座標が変更されるわけではありません。負の座標も通常の整数として扱うので、原点の左上を特別扱いする必要はありません。

`cell-neighbors` は、この関数を8方向について呼び、その結果をリストにまとめます。

```racket
(define (cell-neighbors cell)
  (list (shift-cell cell -1 -1)
        (shift-cell cell 0 -1)
        (shift-cell cell 1 -1)
        (shift-cell cell -1 0)
        (shift-cell cell 1 0)
        (shift-cell cell -1 1)
        (shift-cell cell 0 1)
        (shift-cell cell 1 1)))
```

ずらす量が両方0になる組は入れていません。それを入れると、中央の生セル自身まで近傍として数えてしまいます。8個あることを確かめるだけでなく、中央が含まれないこともテストする理由です。全コードには、この二つを確認する例を置いてあります。

ここで作ったのは「近傍の位置のリスト」です。その場所が生きているかどうかは、まだ調べていません。位置を列挙する仕事と、生死を調べる仕事を分けると、それぞれの入力と出力がはっきりします。

近傍のリストを先頭と残りに分け、生きているときだけ1を足します。

```racket
(define (count-alive-in neighbors live)
  (cond
    [(empty? neighbors) 0]
    [(member-posn? (first neighbors) live)
     (+ 1 (count-alive-in (rest neighbors) live))]
    [else (count-alive-in (rest neighbors) live)]))

(define (count-neighbors cell live)
  (count-alive-in (cell-neighbors cell) live))

(check-expect (count-neighbors (make-posn 2 2) blinker-h) 2)
(check-expect (count-neighbors (make-posn 2 1) blinker-h) 3)
```

第1章は「見つかるか」、ここは「何個あるか」ですが、空と残りに分ける考え方は共通です。

### 再帰の答えを使って足す

`count-alive-in` の入力は、調べる位置のリスト `neighbors` と、生セルのリスト `live` です。どちらも座標のリストですが、役割が異なります。一方は順に調べて短くしていくもの、もう一方は生死を調べるために繰り返し参照するものです。

空の近傍リストなら、調べる位置が残っていないので答えは0です。先頭が生きていれば、先頭の1個と、残りの近傍で数えた個数を足します。死んでいれば、先頭からは何も足さず、残りで数えた答えをそのまま返します。

たとえば調べる位置が三つあり、生・死・生だったとします。最後の生の位置を調べた呼出しは、空の答え0に1を足して1を返します。その前の死の位置は1をそのまま返します。最初の生の位置はその1にもう1を足して、合計2を返します。「残りの答えを受け取ってから、自分が担当する1個分を加える」という読み方です。

第1章の所属判定では、見つかるとすぐに真を返せました。個数を数える場合は、一つ見つかっても、後ろにさらに生セルがあるかもしれません。そのため、見つかった枝でも残りを調べます。同じ再帰でも、求める答えによって終了の仕方と結果のまとめ方が変わります。

ブリンカーの中央 `(2,2)` の近傍には左右の2個があります。中央自身は数えないので答えは2です。その一つ上の `(2,1)` は今は死ですが、斜め下・真下の3個が近傍にあるので答えは3です。この二つを先ほどの規則に渡すと、中央は生存し、一つ上には新しく誕生すると分かります。

## 2.3 死んでいるセルも候補に入れる

生きているセルだけを調べると、新しく生まれるセルを見逃します。調べる候補は「現在の生セルと、その周囲8マス」です。それ以外は生きた近傍が0個なので誕生しません。

全コードでは `add-unique` が重複を避けて座標を加え、`union-list` が二つのリストをまとめます。`fold-add-neighbors` は生セルを一つずつ読み、集めた候補 `acc` にその近傍を足していきます。`acc` は途中結果を受け渡す引数です。最初に生セル自身を入れ、`candidate-cells` で候補がそろいます。

### 同じ位置を一度だけ集める

候補を手で書き出すと、一つの死セルが複数の生セルの近傍になる場合があります。近傍リストをただつなげるだけでは、同じ座標が何度も入ります。そのまま次の盤面に採用すると、重複のない盤面という約束が崩れます。

そこで、「まだなければ足す」という小さな関数を作ります。すでにあれば元のリストを返し、なければ `cons` で先頭に加えます。`cons` の第1引数は加える要素、第2引数はその後ろに続くリストです。

```racket
(define (add-unique x xs)
  (cond
    [(member-posn? x xs) xs]
    [else (cons x xs)]))

(check-expect (add-unique (make-posn 1 2) blinker-h) blinker-h)
(check-expect (add-unique (make-posn 0 0) empty)
              (list (make-posn 0 0)))
```

二つのリストをまとめるときは、一方の先頭をもう一方へこの関数で足し、残りについて同じことを繰り返します。それが `union-list` です。足し終えた側を次の呼出しへ渡すので、後から同じ座標が来ても、すでにあると分かります。

```racket
(define (union-list a b)
  (cond
    [(empty? a) b]
    [else (union-list (rest a) (add-unique (first a) b))]))
```

たとえば、左側が座標PとQのリスト、右側がQだけのリストだとします。まずPを右側に足すと、PとQのリストになります。次にQを足そうとしても、もうあるので増えません。左側を最後まで読み終えると、右側に集めたPとQを返します。最初の右側に重複がなければ、途中でも重複を新しく作りません。

### 集めた途中結果を次へ渡す

全コードの `add-neighbors-of` は、一つの生セルの8近傍を、集めかけの候補へまとめる関数です。その関数を、生セルのリストの先頭から順に使います。

```racket
(define (add-neighbors-of cell acc)
  (union-list (cell-neighbors cell) acc))

(define (fold-add-neighbors cells acc)
  (cond
    [(empty? cells) acc]
    [else (fold-add-neighbors (rest cells)
                              (add-neighbors-of (first cells) acc))]))

(define (candidate-cells live)
  (fold-add-neighbors live live))
```

`cells` はまだ近傍を集めていない生セル、`acc` はすでに集まった候補です。先頭の生セルを一つ処理すると、`cells` は一つ短くなり、`acc` にはその近傍が加わります。処理前のリストと処理後のリストが二つの引数で区別されているので、今どこまで進んだかを表せます。

`acc` は「集めたもの」を受け渡すための名前です。特別な命令ではなく普通の引数で、蓄積するものという意味でアキュムレータとも呼びます。`count-alive-in` が残りの答えを待ってから1を足したのに対し、この関数は途中結果を作って次の呼出しに渡します。最後に未処理の生セルが空になったら、集め終えた `acc` が答えです。

最初の呼出しが `live live` なのは、二つの役割の引数に同じ現在盤面を渡すからです。最初の `live` は「これから近傍を集める生セル」、二つ目は「最初から候補に含めておく現在の生セル」です。同じ値を渡しても、その後の役割は違います。

無限の盤面から有限個の候補だけを選べる理由も確認します。候補に入らなかった座標は、現在の生セルでも、その近傍でもありません。もし生きた近傍が一つでもあれば、その生セルの周囲を集めたとき候補になるはずです。したがって候補外の位置は近傍0で、次も死と分かります。調べる範囲を小さくしても、誕生を見逃さない根拠はここにあります。

候補を選別する本体は次です。

```racket
(define (filter-next candidates live)
  (cond
    [(empty? candidates) empty]
    [(next-alive? (member-posn? (first candidates) live)
                  (count-neighbors (first candidates) live))
     (cons (first candidates)
           (filter-next (rest candidates) live))]
    [else (filter-next (rest candidates) live)]))

(define (next-generation cells)
  (filter-next (candidate-cells cells) cells))
```

`cons` は残りの結果の先頭にセルを一つ加えます。再帰で変わるのは候補の残りだけで、判定に使う `live` は毎回同じです。これで、更新途中のセルを参照してしまう誤りを避けられます。

### 判定とリスト作りをつなぐ

`filter-next` の長い条件式を、内側から読みます。まず候補の先頭について、`member-posn?` が現在の生死を求め、`count-neighbors` が生きた近傍数を求めます。その二つの答えを `next-alive?` に渡すと、次に生きるかが決まります。

次に生きるなら、残りの候補を処理した答えの先頭に、この座標を `cons` で加えます。次に死ぬなら、残りの処理結果をそのまま返します。空の候補リストからは空の結果を返すので、この手順を繰り返すと「次に生きると判定された座標だけのリスト」ができます。

現在の盤面と結果のリストは別の値です。元のリストからセルを消していく方法にすると、後で調べるセルが更新済みの状態を見てしまうおそれがあります。ここでは現在の盤面を読むための `live` を固定し、出力用のリストを新しく作ります。すべての判定が同じ世代を参照するという規則を、引数の渡し方で守っています。

最後の `next-generation` は、この二段階を名前でまとめています。先に候補を求め、それと現在盤面を `filter-next` に渡すだけです。長い仕事でも、各関数の入力と出力が決まっていれば、全体の説明は短い式にできます。短く書けることより、その短い式の下にある各部品を説明できることを目指しましょう。

ブリンカーなら、元の左右のセルは近傍が1個なので死にます。中央は近傍2個で生き残り、中央の上下は死セルで近傍3個なので誕生します。その結果が縦の3個です。生き残る位置と新しく生まれる位置を両方選んでいることを、座標の図で確認してください。

練習：候補を生セルだけにしたら、ブリンカーのどの誕生を見逃すでしょうか。紙で予想してから、全コードの `candidate-cells` を一時的に変更してテストの失敗を確認し、元に戻してください。
