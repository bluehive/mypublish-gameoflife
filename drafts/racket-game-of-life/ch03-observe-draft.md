計算結果は座標のリストです。並び順が異なっても同じ盤面なので、リスト同士をそのまま比べるとテストが失敗することがあります。全コードの `same-world?` は座標をx、次にyの順にそろえて比較します。

## 盤面として同じかを考える

第1章で、盤面のリストの順序には意味を持たせないと決めました。ところが、リストという値には順序があります。たとえば座標P、Qをこの順に並べたものと、Q、Pの順に並べたものは、リストとしては異なります。この違いを無視して「同じ場所が生きている」と確かめる必要があります。

全コードでは、比較する両方のリストを同じ規則で並べ直します。xが小さい座標を先にし、xが同じならyが小さい座標を先にします。これで、生セルの組合せが同じなら、両方が同じ並びになります。盤面に重複がないという約束の下で、並べ直した後に `equal?` で比較できます。

並べ直しを担当するのが `sort-cells`、そのために座標の前後関係を決めるのが `cell<?`、一つの座標を順序どおりの位置に入れるのが `insert-cell` です。`insert-cell` は、先頭より前に入るならそこで加え、そうでなければ先頭を残して、残りの適切な位置を探します。空まで来たら、その位置に入れます。

この比較用の部品は、ライフゲームの規則そのものとは別です。最初は `same-world?` を「リストの順序をそろえて比較する道具」として使い、必要に応じて全コードの三つの関数を読めば構いません。規則を変えるときに、比較の仕組みまで同時に変える必要はありません。

## 3.1 小さな既知の答えを使う

2×2のブロックは変化せず、ブリンカーは2世代で元に戻ります。

```racket
(check-expect (next-generation empty) empty)
(check-expect (same-world? (next-generation block) block) #true)
(check-expect
 (same-world? (next-generation blinker-h) blinker-v) #true)
(check-expect
 (same-world? (next-generation blinker-v) blinker-h) #true)
```

空の盤面・静止する配置・変化する配置を分けて確認すると、誕生と生存の取り違えを見つけやすくなります。失敗したら、全体を眺める前に `next-alive?`、`count-neighbors`、候補の順に小さな入力で調べましょう。

### 全体の正解を手で確かめる

ブロックの4個の生セルには、それぞれ他の3個が近傍として存在します。そのため全員が生存します。ブロックのすぐ外の死セルは、生きた近傍が多くても2個なので誕生しません。生き残ることだけでなく、外に余計なセルが生まれないことまで確かめて、次も同じ盤面だと判断します。

ブリンカーの横から縦への変化は前章で調べました。縦から横の場合も、中央が生き残り、上下の端が死に、左右へ誕生します。二つの向きのテストを用意すると、xとyを取り違えた処理や、ある方向の近傍を書き忘れた処理に気づく手掛かりになります。

空の盤面も大切です。生セルがなければ候補も空で、次世代も空です。小さすぎてつまらない入力に見えても、再帰の終わる枝を直接確かめています。大きな配置で何となく動くことを確かめるより、原因を絞りやすい例です。

### 失敗したら小さい問いへ戻る

たとえばブリンカーが次世代で空になったとします。いきなり関数全体を書き直す前に、中央セルの近傍数が2かを確かめます。2なら、その数と現在の生死を `next-alive?` に渡した結果を調べます。ここまで正しければ、その座標が候補に入り、選別後のリストに残るかを調べます。

反対に近傍数が間違っていたら、8方向の座標と、それぞれの所属判定まで戻ります。「最後の結果が違う」から「どの部品への入力と出力が違うか」へ問題を小さくするのです。すでに通っているテストは残しておき、修正が他の部品を壊していないことも一緒に確かめます。

## 3.2 座標を文字の行にする

表示では生を `"#"`、死を `"."` に変えます。`char-at` は1マス、`row-from` は1行、`rows-from` は行のリストを作ります。全コードの `world->rows` がそれらをまとめます。

```racket
(check-expect
 (world->rows blinker-h 0 0 5 5)
 (list "....." "....." ".###." "....." "....."))
(check-expect
 (world->rows (next-generation blinker-h) 0 0 5 5)
 (list "....." "..#.." "..#.." "..#.." "....."))
```

引数の `0 0` は表示範囲の左上、`5 5` は幅と高さです。BSLでは結果が `cons` の連なりとして表示される場合もありますが、同じ行のリストです。この範囲の外にある生セルも、次世代の計算には含まれています。

### 1マスから1行へ進める

`char-at` は、表示したい座標を `make-posn` で作り、そこが生きているかを第1章の関数に尋ねます。生きていれば文字列 `"#"`、そうでなければ `"."` を返します。ここでも、新しい生死判定の方法を作る必要はありません。

```racket
(define (char-at live x y)
  (if (member-posn? (make-posn x y) live) "#" "."))

(check-expect (char-at blinker-h 1 2) "#")
(check-expect (char-at blinker-h 0 2) ".")
```

1行分を作るには、左から右へ位置を一つずつ進め、そのマスの文字列をつなぎます。全コードの `row-from` では、左端のx座標を `ox`、そこから何マス進んだかを `i` とします。現在のx座標は `(+ ox i)` です。`i` が幅に達したら、これ以上表示するマスはないので空文字列を返します。

```racket
(define (row-from live ox y i width)
  (cond
    [(>= i width) ""]
    [else (string-append (char-at live (+ ox i) y)
                         (row-from live ox y (add1 i) width))]))
```

`add1` は1を足す関数です。幅が5なら、最初の `i` は0で、表示する位置は0、1、2、3、4の五つです。次の5で終了します。0から始めるので最後が4になることを、マスを五つ描いて確かめてください。表示する文字は `string-append` で左から順につながります。

ここでは `rest` でリストを短くする代わりに、`i` を増やして終了へ近づいています。幅と `i` の差、つまり残っているマスの数が減ると考えれば、止まる理由を説明できます。幅と高さは0以上の整数を渡す約束です。幅0なら1行は空文字列になります。

### 1行から行のリストへ進める

`rows-from` は、今度は上から下へ進みます。左上のy座標を `oy`、そこからの行数を `j` とし、現在のy座標を `(+ oy j)` とします。その行を `row-from` で作り、残りの行のリストの先頭へ `cons` で加えます。

```racket
(define (rows-from live ox oy j height width)
  (cond
    [(>= j height) empty]
    [else (cons (row-from live ox (+ oy j) 0 width)
                (rows-from live ox oy (add1 j) height width))]))

(define (world->rows cells origin-x origin-y width height)
  (rows-from cells origin-x origin-y 0 height width))
```

一つの行の中では文字列をつなぎ、複数の行はリストにまとめています。`row-from` の終了時が空文字列で、`rows-from` の終了時が空リストなのは、出力の種類が違うからです。何も残っていない場合の答えは、いつも0になるのではなく、その関数が返す値の種類から決まります。

`world->rows` は、表示に必要な引数をまとめて受け取り、行の番号を0から始めます。外から使うときに、毎回開始番号まで指定しなくてよい形にしています。複雑な計算を補助関数に分け、使う側には必要な設定だけを見せる方法です。

### 表示範囲と計算範囲を混同しない

左上が `(0,0)` で幅5、高さ5なら、見えるのはxとyがそれぞれ0から4の範囲です。見せる範囲を変えても、`next-generation` へ渡す生セルのリストは変えません。表示の外側にいる生セルが、内側のセルの近傍になることもあります。

たとえばyが0の行に、xが-1、0、1の3個を並べます。表示をxが0だけの細い範囲にしても、xが-1の生セルは存在します。次世代では `(0,1)` の近傍が3個なので誕生します。見えていないからといって先に捨てると、この誕生を計算できません。

表示用の関数が返すのは、盤面から読み取った文字列のリストです。それを次世代計算の入力には使いません。「計算のための座標のリスト」と「見るための文字列のリスト」を分けておくことで、表示の大きさを変えても規則の計算をそのまま使えます。

## 3.3 自分の予想をテストにする

練習：生セルを一つだけ置きます。次世代が空になる理由を説明し、次のテストを追加してください。

```racket
(check-expect (next-generation (list (make-posn 0 0))) empty)
```

次に、自分で小さな配置を作り、紙で1世代を計算してからテストにしてください。観察した結果をそのまま正解として写すのではなく、規則から期待値を決めます。

### 予想から検証までを一巡する

一つだけの生セルの周囲には、他の生セルがありません。近傍0なので、そのセルは次に死にます。周囲の死セルから見ても、生きた近傍は1個までなので誕生しません。したがって次世代は空です。元のセルの生死だけを見ず、周囲の誕生も調べて答えを決める練習になります。

次の練習では、2個だけの生セルを横に並べてみましょう。二つとも生きた近傍は1個なので死に、他の場所も近傍3個にはなりません。答えはやはり空です。次に3個の横並びにすると、すでに扱ったブリンカーになります。入力を一つずつ増やすと、どの条件を境に誕生が起こるかを比べられます。

自分の配置を試すときは、最初から何十個も置く必要はありません。生セルを数個にとどめ、周囲8マスを紙で数えられる大きさにすると、期待値を自分で作れます。一世代分が合えば、さらにその結果を入力にして次を調べます。同じ関数を結果にもう一度適用するだけで、二世代目を計算できます。

テストに成功したことは、書いた例について期待値と一致したという証拠です。まだ試していないすべての配置まで正しいと自動的に決まるわけではありません。そのため、例だけでなく「候補の外では誕生しない」「同じ現在盤面を参照する」「再帰は終了に近づく」といった理由も、コードと対応させて確認しました。具体例と、その手順でよい理由の両方を使って理解を確かめてください。

ここまでで、データを決め、小さな関数をテストし、それらを組み合わせて盤面を更新できました。新しい題材でも「何を入力し、何を返すか」「小さな正解の例は何か」から始めてみましょう。
